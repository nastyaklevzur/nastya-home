# PRD: Рекомендательная система v2 для «Дома Насти»

Версия 1.0 · 3 ноября 2026 · Статус: на согласовании
Исследование и протокол решений: [recsys-v2-research.md](recsys-v2-research.md)

## 1. Зачем

Сейчас ряд «Топ-10 рекомендаций кино» — это десять фильмов, которые Claude подбирает раз в неделю по описанию вкусов
из промпта. Настя может только пометить фильм «Начала смотреть» / «Просмотрено», и эти метки никуда не уходят.
Подборка не знает, что ей понравилось, что она отвергла, не умеет убирать просмотренное и не следит за новинками.

Цель v2 — превратить ряд в живую подборку, которая:
1. реагирует на действия Насти сразу (убрал — на место встал другой фильм);
2. учится на её оценках и со временем попадает точнее;
3. всегда содержит три свежих фильма и показывает, какие из фильмов отмечены премиями;
4. не требует от Насти ничего, кроме пульта, и ничего лишнего не добавляет на экран.

### Метрики успеха (смотрим через месяц после релиза)
- Доля просмотренных фильмов, у которых есть оценка «Нравится / Не нравится» — не меньше 60 %.
- Ряд никогда не пустой и всегда показывает 10 карточек (если в пуле ≥ 10 доступных).
- Доля «Не буду смотреть» среди действий падает от недели к неделе (подборка попадает точнее).
- Ежедневная задача на Mac отрабатывает без ручного вмешательства ≥ 5 дней из 7.

## 2. Термины

| Термин | Значение |
|---|---|
| **Пул** | 30–40 фильмов в `movies.json`, отобранных и отранжированных Claude на Mac. Настя видит только часть. |
| **Ряд (топ-10)** | 10 карточек на главном экране, собираются проектором из пула по правилам §6. |
| **Закреплённый** | Фильм, который Настя хочет посмотреть на днях. Стоит в начале ряда, не ротируется. Максимум 3. |
| **Избранное** | Долгий список «хочу посмотреть когда-нибудь». Отдельный экран, на ряд не влияет. |
| **Удалённый** | Фильм со статусом «Просмотрен» или «Не буду смотреть». Из ряда исчезает, в пул больше не попадает. |
| **Скрытые** | Вкладка на экране избранного: все удалённые, откуда фильм можно вернуть. |
| **Оценка** | «Нравится» / «Не нравится», ставится только после «Просмотрен». Главный сигнал для рек.системы. |
| **Новинка** | Фильм, вышедший за последние 18 месяцев, у которого уже состоялся цифровой релиз. |
| **Состояние** | `state.json` — всё, что сделала Настя. Владелец — проектор, Mac только читает. |
| **Лёгкий прогон** | Ежедневная задача на Mac: прочитать состояние, убрать удалённые из пула, пересчитать порядок. |
| **Большой прогон** | Еженедельная задача (понедельник): новинки, рецензии, премии, профиль вкусов, обновление до трети пула. |

## 3. Пользовательские сценарии

Управление — пульт: стрелки, OK, Назад, Menu. На проекторе долгое нажатие OK перехватывает система, поэтому
вход в меню карточки — кнопка **Menu** (под рядом постоянная подсказка «Menu — действия с фильмом»).

### SC-1. Открыть меню фильма
1. Фокус на карточке → Menu.
2. Диалог с заголовком «Название (год)» и пунктами по порядку:
   «О фильме» · «Закрепить» / «Открепить» · «В избранное» / «Убрать из избранного» · «Просмотрен» · «Не буду смотреть» ·
   «Сбросить метку» (только если стоит «Начала смотреть»).
3. Назад закрывает меню без действий.

**AC:** меню открывается за ≤ 300 мс; формулировки пунктов зависят от текущего состояния фильма (toggle); OK на карточке
по-прежнему сразу запускает поиск в LAMPA и ставит «Начала смотреть», как в v1.

### SC-2. Закрепить / открепить
1. «Закрепить» → карточка перемещается на первую позицию ряда (после уже закреплённых), в левом верхнем углу постера значок кнопки 📌, фокус следует за карточкой.
2. Повторный Menu → «Открепить» → карточка возвращается на место по рангу (может уйти из ряда, если ранг ниже 10-го).
3. Если закреплено уже 3 → тост «Можно закрепить не больше трёх. Открепи что-нибудь», ничего не меняется.

**AC:** закреплённые всегда занимают позиции 1..N (N ≤ 3) в порядке закрепления; большой прогон на Mac никогда не выбрасывает
закреплённый фильм из пула; если фильм всё же пропал из `movies.json`, проектор показывает его из снимка в состоянии (§7).

### SC-3. Просмотрен → оценка
1. «Просмотрен» → сразу второй диалог: «Понравился «Название»?» с кнопками **👍 Нравится** · **👎 Не очень** · «Пропустить».
2. Любой ответ: карточка исчезает, на её место въезжает следующий подходящий фильм из пула (§6), фокус остаётся на той же позиции.
3. Внизу экрана на 6 секунд плашка: «Просмотрен: «Название». Назад — вернуть».
4. Назад в эти 6 секунд → фильм возвращается на своё место, оценка стирается. (Сейчас Назад на главном экране возвращает фокус на ряд кино — `onBackPressed` в `MainActivity`; отмена должна срабатывать раньше этой логики.)

**AC:** диалога «Точно?» нет; оценка и статус записываются в состояние одной записью; если ответ «Пропустить», `liked = null`;
фильм появляется во вкладке «Скрытые» с подписью «Просмотрен 3 ноя · 👍».

### SC-4. Не буду смотреть
1. «Не буду смотреть» → карточка исчезает, следующий фильм встаёт на место, плашка «Убрал: «Название». Назад — вернуть» 6 секунд.
2. Назад → возврат.

**AC:** подтверждения нет; в состоянии `reason = "skip"`, `liked = null`; рек.система трактует это как точечный отказ от фильма,
а не от жанра (§8.4).

### SC-5. В избранное / убрать из избранного
1. «В избранное» → тост «Добавил в избранное ♥», карточка остаётся в ряду как была (в ряду появляется маленькое ♥ рядом с рейтингом).
2. Счётчик на кнопке-сердечке в заголовке ряда увеличивается.
3. «Убрать из избранного» — обратное.

**AC:** избранное не влияет на состав ряда; Mac может ротировать такой фильм из пула, но на экране избранного он остаётся (снимок).

### SC-6. Экран «Избранное»
1. В строке заголовка ряда справа кнопка «♥ 7» (число = размер избранного; при нуле — просто «♥»). Фокусируется стрелками как обычный элемент, OK открывает экран.
2. Экран: две вкладки сверху — «Избранное» и «Скрытые», переключение стрелками влево/вправо на вкладках; ниже сетка карточек (та же карточка, что в ряду, 5 в строке, вертикальная прокрутка).
3. На карточке в «Избранном»: OK → поиск в LAMPA; Menu → «О фильме» · «Закрепить» · «Просмотрен» · «Убрать из избранного».
4. На карточке в «Скрытых»: подпись под названием «Просмотрен 3 ноя 👍» / «Не буду смотреть 1 ноя»; OK или Menu → «Вернуть в подборку» · «О фильме».
5. «Вернуть в подборку» → запись удаляется из `removed`, фильм снова может попасть в ряд (если ещё есть в пуле — сразу, иначе — после большого прогона).
6. Назад → главный экран, фокус на кнопке ♥.

**AC:** пустое избранное — текст «Нажми Menu на фильме и выбери «В избранное»»; пустые «Скрытые» — «Тут появятся просмотренные
и убранные фильмы»; экран открывается офлайн (данные локальные, постеры из кэша Coil или вшитой копии).

### SC-7. Замена удалённого фильма
1. После SC-3/SC-4 на освободившуюся позицию встаёт фильм из пула с лучшим рангом, которого нет в ряду и в удалённых; если в ряду стало меньше трёх новинок, а удалённый был новинкой — берётся лучшая новинка.
2. Анимация: карточка схлопывается, соседи сдвигаются, новая появляется с затемнения (≤ 250 мс).

**AC:** в ряду никогда нет дубликатов; если доступных фильмов < 10, ряд короче (без заглушек), а лёгкий прогон на Mac доливает пул.

### SC-8. Обновление подборки без «перетасовки под рукой»
1. Проектор, как и сейчас, скачивает `movies.json` раз в час и по кнопке «Обновить».
2. Новый пул **применяется** к ряду только при холодном старте, по кнопке «Обновить» или если лаунчер не был на экране > 10 минут (тот же порог, что у заставки).
3. При применении: закреплённые — первыми; карточки, которые были в ряду и остались в пуле, сохраняют позиции; выбывшие заменяются по §6.

**AC:** пока Настя листает ряд, порядок не меняется; после возвращения из фильма ряд может обновиться — это ожидаемое поведение.

### SC-9. Значок премий и расширенный экран «О фильме»
1. На карточке, если у фильма есть `award_badge`, под рейтингом золотая плашка: «🏆 Оскар» / «Номинант «Оскара»» / «Канны» / «Золотой глобус» / «BAFTA» (одна, самая значимая).
2. Экран «О фильме»: постер, название и оригинальное название, строка «1994 · 142 мин · США · драма, мелодрама», рейтинги «IMDb 8.8 · Кинопоиск 8.9», награды списком («6 «Оскаров», в т. ч. лучший фильм»), «Почему тебе» (`why_you`), «Критики» (`critics`), описание (`note`).
3. Кнопки: «Искать в LAMPA» (фокус по умолчанию), «Закрепить/Открепить», «В избранное/Убрать», «Просмотрен», «Не буду смотреть», «Назад».

**AC:** все поля опциональны — отсутствующие строки не показываются и не оставляют пустых мест; после «Просмотрен» / «Не буду смотреть» экран закрывается и срабатывает SC-3/SC-4.

### SC-10. Синхронизация состояния в GitHub (невидимо для Насти)
1. Каждое действие сразу сохраняется локально, через 5 секунд тишины (чтобы несколько действий слились в один коммит) проектор отправляет `state.json` в репозиторий.
2. Нет сети / ошибка → файл помечается «не отправлен», повтор при следующем `refreshAll` (раз в час), при старте и после успешной загрузки `movies.json`.
3. При старте с пустым локальным состоянием (новая установка, `pm clear`) проектор скачивает `state.json` из репозитория и восстанавливает всё.

**AC:** Настя не видит ни одного сообщения об ошибке синхронизации; в репозитории появляется коммит вида
«📺 Настя: просмотрен «Амели» 👍, закреплён «Семь»»; Mac в отчёте лёгкого прогона пишет «состояние с проектора старше 3 дней», если это так.

### SC-11. Лёгкий прогон на Mac (ежедневно)
1. `git pull`, прочитать `state.json`, `movies.json`, `history.json`.
2. Все `removed` → в `history.json` со статусом, из пула удалить. Снять с пула фильмы, которых Настя не трогала > 60 дней и ранг которых ниже 20 (ротация), кроме закреплённых и избранных.
3. Если в пуле < 30 — Claude подбирает недостающие (5–10) по профилю вкусов и обогащает их (§8.2).
4. Пересчитать ранги с учётом новых оценок (§8.4), записать `movies.json`, запушить.

**AC:** прогон ≤ 5 минут при отсутствии новых кандидатов; в отчёте — что убрано, что добавлено, сколько в пуле, возраст состояния.

### SC-12. Большой прогон на Mac (понедельник)
Всё из SC-11 плюс: свежие кандидаты из TMDB/Кинопоиска (новинки, тренды, премьеры в России), премии из Wikidata/OMDb,
2–3 рецензии на каждого нового кандидата, обновление `taste.json`, замена до трети пула.

**AC:** в пуле ≥ 8 новинок по определению §2; не больше 2 фильмов одного режиссёра; ни одного из `history.json` со статусом удалён;
у каждого фильма есть постер в `posters/`.

## 4. Ошибочные сценарии

| # | Ситуация | Поведение |
|---|---|---|
| ERR-1 | Нет интернета при действии | Действие применяется локально, отправка откладывается (SC-10). Без сообщений. |
| ERR-2 | GitHub отвечает 401/403 (токен отозван) | Локально всё работает; проектор пишет ошибку в logcat; Mac сообщает в отчёте «состояние не обновлялось N дней». |
| ERR-3 | GitHub 409 (sha устарел) | Повторить GET sha → PUT, до 3 раз. Единственный писатель — проектор, конфликтов по содержимому нет. |
| ERR-4 | В пуле < 10 доступных фильмов | Ряд короче, лёгкий прогон доливает. Если < 3 — в заголовке «обновлено …» добавляется «подборка пополняется». |
| ERR-5 | Нет новинок, проходящих порог | Квота новинок заполняется лучшими из доступных, в отчёте Mac — предупреждение. |
| ERR-6 | Закреплённый или избранный фильм пропал из пула | Показывается из снимка в состоянии (§7); постер — из кэша или заглушка. |
| ERR-7 | Старый APK (v1) + новый `movies.json` | v1 берёт первые 10 по порядку файла = топ пула по рангу. Работает. |
| ERR-8 | Новый APK + старый `movies.json` (v1) | Все фильмы считаются пулом, `is_new = false`, без значков премий. Работает. |
| ERR-9 | На проекторе сбиты часы | Метки времени в состоянии могут быть странными; Mac использует порядковый номер действия `seq`, а не время, для «что новее». |
| ERR-10 | Mac выключен несколько дней | Проектор живёт на пуле: при 1–3 просмотрах в неделю пула хватает на 2–3 недели. |
| ERR-11 | TMDB недоступен с Mac (DNS-подмена провайдером) | Скрипт ходит через DoH и `--resolve` (см. research §2); если и это не работает — большой прогон использует только Кинопоиск-API и OMDb и пишет предупреждение. |
| ERR-12 | Исчерпан дневной лимит OMDb (1000) или Кинопоиск-API (500) | Обогащение откладывается на следующий прогон, фильм публикуется с тем, что есть. |

## 5. Экран и элементы

- **Заголовок ряда:** «Топ-10 рекомендаций кино   обновлено 3 ноября» + справа фокусируемая кнопка «♥ 7».
- **Подсказка под рядом:** «Menu — действия с фильмом», 10.5 sp, 65 % прозрачности (как у `meta`).
- **Карточка (100×150 dp постер):** рейтинг справа вверху (как сейчас); 📌 слева вверху у закреплённых; ♥ у избранных рядом с рейтингом;
  плашка премии золотая под рейтингом; плашка статуса «Начала смотреть» снизу (как сейчас). Больше трёх значков одновременно не бывает (📌, ♥, премия).
- **Плашка «Назад — вернуть»:** полоса внизу экрана поверх ряда приложений, 6 секунд, без перехвата фокуса. Кнопка Назад в эти 6 секунд обрабатывается как отмена; после — как обычно.
- **Экран «Избранное»:** см. SC-6. Стиль — как `activity_details` (тёмный фон, кремовый текст).
- **Экран «О фильме»:** см. SC-9. Всё помещается на 960×540 без прокрутки: постер слева 240×360, текст справа, кнопки в один ряд внизу.

## 6. Алгоритм сборки ряда (на проекторе)

Вход: пул `P` (отсортирован по `rank`), состояние `S`, текущий ряд `R` (сохранён в SharedPreferences как список `tmdb_id`).

```
available = P без S.removed
pinned    = S.pinned (в порядке закрепления) без S.removed      // ≤ 3, берём данные из P или из снимка
row       = pinned
keep      = [id ∈ R | id ∈ available, id ∉ pinned]               // стабильность: оставляем, что было
row      += keep (в прежнем порядке), пока |row| < 10
needNew   = max(0, 3 − count(row, is_new))
while |row| < 10:
    next = первый из available ∉ row, причём если needNew > 0 — первый с is_new = true (если такие есть)
    row += next; если next.is_new: needNew −= 1
```

- Замена одной карточки (SC-7) — тот же цикл для одной позиции: `next` вставляется на место удалённой, а не в конец.
- Применение нового пула (SC-8) — полный пересчёт по алгоритму; `R` обновляется и сохраняется.
- Ключ фильма везде — `tmdb_id`. Для файлов v1 без `tmdb_id` ключ — `title|year` (совместимость).

- `rating` сохраняется для v1 и равен `imdb_rating` (если нет — `kp_rating`). На карточке показывается `rating`.
- `why_you` ≤ 90 символов, `critics` ≤ 160, `note` ≤ 48 (как в v1).
- `award_badge` выбирает Mac по приоритету: Оскар (победа) → Номинант «Оскара» → Канны (Пальмовая ветвь) → Золотой глобус → BAFTA → пусто.
- Размер пула: 30–40. Порядок в файле = `rank`.

### 7.2 `state.json` (пишет проектор)

```json
{
  "version": 1,
  "updated": "2026-11-03T21:15:00+02:00",
  "seq": 42,
  "pinned":    [{"id": 807, "at": "2026-11-03T20:01:00+02:00", "snap": {"title": "Семь", "year": 1995, "poster": "posters/se7en.jpg", "note": "…", "search": "Семь"}}],
  "favorites": [{"id": 194, "at": "…", "snap": {…}}],
  "removed":   [{"id": 637, "reason": "watched", "liked": true,  "at": "…", "seq": 41, "snap": {…}},
                {"id": 773, "reason": "skip",    "liked": null,  "at": "…", "seq": 40, "snap": {…}}],
  "started":   [{"id": 137, "at": "…"}]
}
```

- `seq` — счётчик действий, растёт на 1 при каждом изменении; Mac по нему понимает порядок событий даже при сбитых часах.
- `snap` — снимок карточки, чтобы экран избранного и закреплённые работали, когда фильм уже выбыл из пула.
- `reason`: `watched` | `skip`. `liked`: `true` | `false` | `null`.
- Единственный писатель — проектор. Mac читает и никогда не правит (кроме миграции при первом запуске v2, §10).

### 7.3 `history.json` (ведёт Mac)

Расширяется полем `status`: `shown` | `watched` | `skip` | `rotated`, и полями `liked`, `tmdb_id`, `last_seen`.
Фильмы со статусом `watched` и `skip` никогда не предлагаются снова; `rotated` (выбыл по ротации) — можно через 6 месяцев.

### 7.4 `taste.json` (пишет Mac, большой прогон)

Профиль вкусов для промпта: счётчики по жанрам, десятилетиям, странам и режиссёрам среди `liked = true`, `liked = false`,
`favorites`, `skip`; 10 последних оценок с названиями; текстовое резюме Claude ≤ 600 символов («любит тёплые драмы с юмором,
корейские триллеры; не зашли медленные артхаусные…»). Пересобирается каждый понедельник, читается ежедневно.

### 7.5 Ключи и секреты

- GitHub: fine-grained PAT на репозиторий `nastyaklevzur/nastya-home`, право **Contents: Read and write**, срок 1 год.
  Кладётся в `local.properties` как `github.token=…` (файл в `.gitignore`), попадает в `BuildConfig.GITHUB_TOKEN` при сборке (в `app/build.gradle.kts` включить `buildFeatures { buildConfig = true }` и добавить `buildConfigField` из `local.properties`; если ключа нет — пустая строка, синхронизация молча выключена).
- Mac: `~/.config/nastya-home/keys.env` с `TMDB_KEY`, `OMDB_KEY`, `KINOPOISK_KEY`. В репозиторий не попадают.

## 8. Рекомендации (Mac)

### 8.1 Источники кандидатов (большой прогон)
- TMDB `discover` (`region=RU`, `language=ru-RU`, `primary_release_date` за 18 месяцев, `vote_count ≥ 1000`), `trending/week`, `now_playing`/`upcoming` для RU.
- Кинопоиск-API: премьеры в России за текущий и прошлый месяц, коллекции (топ-250, популярное).
- Wikidata: лауреаты и номинанты Оскара, Канн, Глобуса, BAFTA за последние 2 сезона.
- Классика: Claude подбирает по профилю вкусов, как в v1, но с обязательной проверкой рейтингов через OMDb/Кинопоиск.

### 8.2 Обогащение каждого кандидата
OMDb → `imdb_rating`, `imdb_votes`, `metascore`, строка `Awards`; Кинопоиск-API → `kp_rating`, награды, русское название, жанры, страна, режиссёр;
TMDB → `digital_release` (release_dates, type 4), постер w342; Wikidata → структурные награды с русскими метками.
Для новинок Claude читает 2–3 рецензии (Film.ru, Афиша, RogerEbert, Rotten Tomatoes editorial) и пишет `critics`.

### 8.3 Пороги
- Классика: IMDb ≥ 7.5 или Кинопоиск ≥ 7.5.
- Новинка: до 18 месяцев с премьеры, `digital_release` в прошлом, IMDb ≥ 7.0 при `imdb_votes ≥ 10 000` (или Кинопоиск ≥ 7.0 при ≥ 10 000 голосов).
- Только полнометражные, с русской озвучкой с высокой вероятностью (цифровой релиз состоялся, фильм известный).

### 8.4 Ранжирование (правила для промпта и скрипта)
Балл = качество + совпадение со вкусом + новизна − штрафы, затем разнообразие.
- **Качество:** нормированный рейтинг (IMDb и КП, среднее), бонус за премии.
- **Совпадение со вкусом:** близость по жанрам/десятилетию/стране/режиссёру к фильмам с `liked = true` и из избранного; оценки за последние 30 дней весят вдвое больше старых (как у Netflix: недавнее важнее).
- **«Не нравится»:** понижает похожие (тот же режиссёр, та же связка жанров) на одну ступень, но не блокирует.
- **«Не буду смотреть»:** только сам фильм; на похожие не влияет. Если за месяц ≥ 3 «не буду» с одним жанром — Claude отмечает это в `taste.json` как гипотезу и мягко снижает жанр.
- **Новизна:** `is_new` → бонус; в пуле ≥ 8 новинок, в ряду — ровно 3 (гарантирует проектор, §6).
- **Разнообразие:** в топ-10 пула не больше 2 фильмов одного жанра-лидера подряд, не больше 2 одного режиссёра во всём пуле, не больше 1 фильма одной франшизы.
- **Стабильность:** за один большой прогон заменяется ≤ 1/3 пула; закреплённые, избранные и «Начала смотреть» не трогаются.
- **Холодный старт:** пока оценок < 10, вкусовая часть балла = 0, ряд строится по качеству, новизне и описанию вкусов из промпта v1.

### 8.5 Скрипты
`scripts/publish.py` развивается в `scripts/pool.py` с подкомандами:
- `pool.py enrich draft.json` — обогащение (§8.2), скачивание постеров, расчёт `award_badge`, `is_new`;
- `pool.py validate` — размер пула 30–40, уникальные `tmdb_id`, отсутствие удалённых из `history.json`, лимиты длин, постеры на месте, ≥ 8 новинок, ≤ 2 на режиссёра;
- `pool.py publish --push` — записать `movies.json`, обновить `history.json`, коммит «🎬 Подборка для Насти (дата): +3 −2, в пуле 38»;
- `pool.py state` — прочитать `state.json` и напечатать сводку для Claude (новые оценки, удалённые, возраст состояния);
- `pool.py taste` — пересобрать `taste.json` (счётчики; текстовое резюме дописывает Claude).

### 8.6 Задачи Claude Code на Mac
Одна задача `nastya-daily-movies`, ежедневно 09:08; по понедельникам работает в режиме большого прогона (§SC-12), в остальные дни — лёгкого (§SC-11).
Существующая `nastya-weekly-movies` отключается после релиза. Отчёт в конце прогона: что убрано/добавлено, сколько в пуле и новинок, ссылка на коммит, возраст `state.json`, предупреждения.

## 9. Нефункциональные требования
- Проектор: 2 ГБ RAM, Android 9, без Google-сервисов, 32-бит. Никаких новых тяжёлых зависимостей; GitHub API — через `Http.kt`, в который добавляется метод `put` (сейчас там только GET); OkHttp не нужен.
- Все экраны работают офлайн на кэше и вшитой копии `movies.json`/`state.json` (копия состояния в assets не нужна — при отсутствии сети и локального состояния оно просто пустое).
- Проектор не ходит в TMDB, OMDb, Кинопоиск, Wikidata — только GitHub raw/jsDelivr (чтение) и `api.github.com` (запись). Сертификаты GitHub — DigiCert, в Android 9 есть.
- `state.json` ≤ 100 КБ (снимки без описаний длиннее 48 символов); при > 500 записях в `removed` старые (> 1 года) сворачиваются до `{id, reason, liked}`.
- Токен в APK: приложение не публикуется, ключ ограничен одним репозиторием, ротация — пересборка APK.

## 10. Миграция с v1
1. Первый запуск v2: метки из SharedPreferences `watch` переносятся в `state.json`: `watched` → `removed(reason=watched, liked=null)`, `started` → `started`; ключ `title|year` сопоставляется с `tmdb_id` по текущему `movies.json` (все 10 фильмов v1 там есть).
2. Mac при первом большом прогоне v2 переводит `history.json` в новый формат (`status = shown`, `tmdb_id` из текущих и прошлых подборок).
3. `movies.json` v1 продолжает читаться (ERR-8), поэтому порядок выкладки свободный: сначала APK, потом данные, или наоборот.

## 11. Вне scope v2
«Где смотреть» (Кинопоиск/Okko), трейлеры в SmartTube, кино-новости в строке новостей, Trakt, несколько рядов («Под настроение», «Для двоих»),
оценка с телефона, связь с LAMPA (что реально досмотрели), плашка «Новое» на свежедобавленных карточках. Всё это возможно на тех же данных, см. research §2.

## 12. Открытые вопросы
