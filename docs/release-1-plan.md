# Релиз 1 (сборка 5) — вкладки, профиль, «Продолжить просмотр», футер

План написан 4 ноября 2026 (Claude Fable 5.1) для исполнения субагентами на Sonnet. Ветка `claude/release-1-tab-navigation-061ebb`,
worktree `.claude/worktrees/release-1-tab-navigation-061ebb`. Главный документ проекта — `README.md`, правила — `CLAUDE.md`.

## 0. Релизный цикл (как работаем с этого релиза)

1. **Ветка от свежего `main`** (`git fetch origin main`, worktree от `origin/main`). Код в `main` руками не правим.
2. **Коммиты в ветку** — короткие, с эмодзи («✨ …», «🧭 …», «📝 …»), пушим в `origin/<ветка>`.
3. **Перед PR**: `git merge origin/main` → `./gradlew testDebugUnitTest assembleRelease` зелёные.
4. **Версия**: в `app/build.gradle.kts` `versionName = "<релиз>.<минор>"`, `versionCode = <номер сборки>`; номер сборки растёт на 1
   с каждой сборкой, которую ставим на устройство. Этот релиз: **versionName 1.0, versionCode 5**. Футер и экран «О приложении»
   берут версию из `BuildConfig`, руками ничего не дублируем.
5. **PR → ревью → merge** в `main` (merge только после явного «да» пользователя). После merge — тег `v1.0-b5`.
6. **Деплой** = установка APK, собранного из `main` после merge, на проектор по правилам CLAUDE.md §4 (свежий main,
   тесты, согласование с другими сессиями, один установщик).
7. После релиза — абзац в README («Версии»), обновление памятки.

Что было в списке пользователя лишнего/недостающего: лишнего нет; добавлены пункты 3 (merge main + проверка до PR),
4 (бамп версии), тег и правило «деплой только из main».

## 1. Что делаем (фичи релиза)

### F1. Футер: версия и кредиты
Внизу каждого экрана лаунчера тонкая строка (12sp, alpha 0.55, по центру):
`Дом Насти · версия 1.0 (сборка 5) · © 2026 <автор>`. Версия/сборка из `BuildConfig.VERSION_NAME` / `VERSION_CODE`,
год — текущий из `Calendar`, автор — строка `@string/credits_author` (одна строка, легко поменять).

### F2. Профиль: имя пользователя на устройстве
- SharedPreferences `profile`: `name` (String), `asked` (Boolean).
- **Первый запуск** (имя пустое и `asked=false`): после заставки (или сразу, если заставки нет) открывается диалог
  «Как тебя зовут?» с полем ввода и кнопками «Готово» / «Позже». «Позже» ставит `asked=true`, больше не спрашиваем сами.
- **Иконка профиля** 👤 в шапке справа от часов (фокусируемая, chip как `tvFav` раньше). OK — тот же диалог с текущим именем.
- **Приветствие**: `Greetings.forHour(hour, name)`: с именем — «Доброе утро, Настя ☀️», без имени — «Доброе утро ☀️».
  Вторая строка без изменений. Заставка: первая строка — «<Имя>,» (или «Привет,» без имени), вторая — «как я рад тебя видеть! ✨».
  Захардкоженное «Настюшечка, золотце» из кода и strings.xml уходит.
- Имя никуда не синхронизируется (не в `state.json`), это свойство устройства.

### F3. Навигация вкладками (верх экрана)
Четыре вкладки: **Главная · Кино · Камеры LIVE · Приложения**. Правила UI (Android TV best practices):
- Вкладки — ряд фокусируемых «чипов» под самым верхом, слева; переключение **по фокусу** (как на Google TV/YouTube TV),
  без лишнего OK. Стрелка вниз из вкладки уходит в первый фокусируемый элемент страницы.
- Выбранная вкладка подсвечена (кремовый фон, тёмный текст), остальные полупрозрачные; стрелка вверх из контента — в текущую вкладку.
- **Назад**: на вложенном экране — закрыть; на любой вкладке кроме «Главная» — на «Главную» (фокус на вкладку); на «Главной» —
  прежнее поведение (отмена «Вернуть» или фокус на первую карточку). Кнопка Home пульта (`onNewIntent`) — на «Главную».
- Состояние вкладки не сохраняется между запусками: старт всегда на «Главной».
- Реализация: один `MainActivity`, контейнер `FrameLayout` с четырьмя страницами (`include` layout’ов `page_home`, `page_movies`,
  `page_cams`, `page_apps`), видимость по вкладке; данные (ряд топ-10, камеры, состояние) общие, адаптеры по экрану.
  Fragment’ы/ViewPager не вводим — на Android 9 с пультом проще и надёжнее View-переключение.

**Главная** (сверху вниз): шапка (приветствие + погода + часы + 👤) → лента новостей → блок «Кино» с заголовком
«Топ-10 рекомендаций кино» и шильдиком-стрелкой «Кино →» (фокусируемый, OK — вкладка «Кино») → ряд топ-10 →
ряд «Продолжить просмотр» (скрыт, если пусто) → ряд «Онлайн-камеры» (только камеры с `home: true`, шильдик «Все камеры →»).
Сердечко ♥ и ряд приложений с главной уходят. Если всё не влезает в 540 dp — страница прокручивается (ScrollView уже есть),
ряды сами подъезжают при фокусе.

**Кино**: «Рекомендации» (тот же ряд топ-10; последняя карточка — «Показать всё» → экран «Рекомендации»: сетка всего пула
без убранных, по рангу) → «Продолжить просмотр» → «Избранное» (ряд избранных; последняя карточка «Все · Скрытые» → `FavoritesActivity`)
→ «Приложения»: SmartTube, Кинопоиск, LAMPA. Страница вертикально прокручивается.

**Камеры LIVE**: заголовок и сетка всех видимых камер (`VerticalGridView`, 5–6 колонок, плитки как в ряду). OK — плеер.

**Приложения**: крупные плитки RuStore, Настройки, Обновить, VLC (только установленные; «Обновить» всегда).

### F4. «Продолжить просмотр» (новая фича)
Что реально доступно на устройстве без root: у LAMPA и Кинопоиска нет API и доступа к их истории. Поэтому
«недосмотренные» = **фильмы, просмотр которых начат через наш лаунчер**: запись `started` в `state.json` появляется, когда
нажали «Смотреть» (LAMPA) или новый пункт «Смотреть в Кинопоиске». Это честно покрывает сценарий «начала смотреть вчера —
сегодня продолжу»: карточка на главной, OK — открывает фильм в том же приложении.

- `Entry` получает необязательное поле `via` (`"lampa"` | `"kinopoisk"`), пишется в `state.json` только у `started`
  (Mac-скрипты поле игнорируют — формат обратно совместим).
- Список: `state.started`, новые сверху (по `seq`), фильм берётся из пула по ключу или из `snap`. Убранные (`removed`) не показываются.
- Карточка: постер + название + подпись «в LAMPA · 3 ноя» / «в Кинопоиске · 3 ноя». OK — продолжить (LAMPA: `Launcher.openMovieInLampa`;
  Кинопоиск: `Launcher.openMovieInKinopoisk` — `ACTION_VIEW https://www.kinopoisk.ru/film/<kinopoisk_id>/` в пакет `ru.kinopoisk.tv`,
  если не резолвится — просто запуск Кинопоиска). Menu — «Продолжить», «О фильме», «Просмотрен» (с вопросом «Понравился?»), «Сбросить метку».
- В «О фильме» в Menu появляется «▶ Смотреть в Кинопоиске» (только если Кинопоиск установлен); ставит `started` с `via=kinopoisk`.
- Ряд одинаковый на «Главной» и в «Кино» (один источник данных, два адаптера).

### F5. Камеры на главной и шесть камер Рима
- `cams.json`: у камер появляется `home: true` — ряд на «Главной». Набор: Зеленоградск, Волки ×2 (Миннесота), Панды (Мосзоо),
  Река Чобе, Рим ×6. Полная сетка во вкладке — все видимые камеры (как сейчас).
- Рим: сейчас видима только «фонтан Треви», «Колизей» спрятан. Нужны 6 работающих Skyline-камер Рима: Треви, Колизей,
  пьяцца Навона (проверена 2 ноября), пьяцца ди Спанья, панорама Рима (`roma-skyline`), Пантеон/Сан-Пьетро — проверить curl’ом
  с Mac по механике из README (`type: skyline`, `page`), у каждой `preview` (абсолютный og:image/thumbnail со страницы Skyline или
  кадр в `cams/rome-*.jpg`). Непроверенные не включать; если шести не набирается — включить сколько есть и написать в README.
- `CamsParser` читает `home`; если ни у одной камеры нет `home` (старый кэш) — ряд на главной показывает все видимые.

## 2. Деление на субагентов (Sonnet)

Фаза 1 — один агент, последовательно (каркас, от него зависят остальные):

**A. Каркас вкладок + футер + версия (F1, F3)** — `app/build.gradle.kts` (versionName 1.0 / versionCode 5), `activity_main.xml` →
вкладки + четыре `page_*.xml` + футер, `MainActivity.kt` (переключение вкладок, фокус, Назад/Home, общие данные → адаптеры
страниц), `AppCatalog` (группы «кино»/«система»), сетка камер, ряд избранного, «Показать всё» → `RecommendationsActivity`,
убрать ♥ с главной, строки. Ряд «Продолжить просмотр» — заглушка: `HorizontalGridView` + заголовок, скрыты (`GONE`), с id
`rvContinueHome`, `rvContinueMovies`, `tvContinueHome`, `tvContinueMovies`. Сборка и тесты обязательны.

Фаза 2 — параллельно, в одном worktree, файлы не пересекаются кроме точечных правок `MainActivity.kt`:

**B. Профиль (F2)** — новый `Profile.kt` (prefs + диалог ввода имени в стиле `MovieDialogs`), `Greetings.kt`, `Splash`/`view_splash.xml`,
`strings.xml`; в `MainActivity` — иконка 👤, вызов диалога после заставки, имя в приветствии. Тест на `Greetings`.

**C. «Продолжить просмотр» (F4)** — `State.kt` (`via`), `StateStore.setStarted(m, on, via)`, новый `ContinueWatching.kt`
(сборка списка из состояния и пула — чистая функция, тест), `Launcher.openMovieInKinopoisk`, `DetailsActivity` (пункт меню),
`MovieAdapter.caption` для подписи; в `MainActivity` — заполнение двух рядов и меню карточки.

**D. Камеры (F5)** — `cams.json` (home-флаги, камеры Рима), `Cam.kt`/`CamsParser` (`home`), `CamsResolveTest`,
превью в `cams/`, README (раздел камер); в `MainActivity` — фильтр `home` для ряда на главной.

Правила для фазы 2: не запускать Gradle (сборку делает координатор после фазы); правки `MainActivity.kt` — минимальные,
перед каждой правкой перечитывать файл (его одновременно правят другие агенты); не переформатировать чужой код; не коммитить.

Фаза 3 — координатор: сборка, тесты, починка, прогон по экрану на проекторе (если свободен), README, коммиты, PR.
