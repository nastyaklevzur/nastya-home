# Правила работы над проектом «Дом Насти»

Проектор один и стоит у Насти дома — это прод. С репозиторием одновременно работают несколько сессий Claude,
поэтому порядок такой: **ветка → слияние main → проверка → согласование → установка**. Прод не используем как стенд.

## 1. Ветки и worktree

- Каждая задача идёт в своей ветке и своём worktree (`.claude/worktrees/<имя>`). В основной папке проекта и в `main` напрямую
  не правим код, не коммитим и не пушим.
- Единственное исключение для `main` — публикация данных скриптами (`scripts/publish.py`, будущий `scripts/pool.py`):
  `movies.json`, `history.json`, `posters/`. Руками эти файлы не правим.
- Коммиты короткие, с эмодзи в начале, как в истории репозитория («✨ …», «📹 …», «📝 …», «🎬 …»).
  Секреты (`local.properties`, ключи API, токен GitHub) в коммиты не попадают.

## 2. Слияние main в ветку

- Перед началом работы и **перед каждой установкой на проектор**: `git fetch origin main && git merge main` (в worktree — через
  инструмент синхронизации с базовой веткой, если он работает, иначе обычный `git merge main`).
- Конфликты решаем так, чтобы сохранить правки обеих сторон (README, `cams.json` — берём обе). После слияния сборка и тесты
  обязательны.
- В `main` ветка попадает только через pull request или после явного «да» пользователя. Сами в `main` не пушим.

## 3. Проверка до проектора

- `./gradlew testDebugUnitTest` — все юнит-тесты зелёные.
- `./gradlew assembleRelease` — сборка проходит на ветке **с влитым main**.
- Логику проверяем юнит-тестами. Проектор — только для финальной проверки на устройстве.

## 4. Установка на проектор (прод)

Ставим только если выполнено всё:
1. В ветке влит свежий `main`, сборка и тесты проходят.
2. Нет другой сессии, которая сейчас работает с проектором: посмотри список сессий, спроси их через SendMessage
   («экран и установка свободны?») и дождись ответа. Один установщик за раз.
3. Пользователь не против (если он просил не трогать проектор — не трогаем).

При установке:
- Говорим остальным сессиям, что и откуда установлено: ветка, хэш коммита, что в сборке есть из `main`.
- Не затираем чужую установку сборкой без актуального `main`: так пропадают чужие изменения (камеры, данные, фиксы).
- Не меняем состояние Насти ради теста. Тестовые нажатия — минимум, потом возвращаем как было (кнопка «Вернуть»,
  «Убрать из избранного», «Открепить»). `pm clear` и любое стирание данных на проекторе — только с прямого разрешения.
- Не ставим на проектор новые приложения и не трогаем accessibility-сервисы без явной просьбы (см. памятку проекта).
- Если нужен экран для проверки: ADB-ввод по пульту отстаёт, нажимаем по одной клавише с паузой и смотрим скриншот.

## 5. Релиз

- Релиз = слияние ветки в `main` (PR) + установка проверенной сборки на проектор по правилам §4.
- Данные подборки и камер публикуются в `main` отдельно (скриптами) и подхватываются проектором без пересборки.
- После релиза обновляем README и памятку проекта.

## 6. Если правила нарушены

Скажи об этом сразу, перечисли, что затронуто (какая сборка стоит на проекторе, чьи изменения затёрты), собери и установи
исправленную сборку по §4 и сообщи пострадавшим сессиям.
